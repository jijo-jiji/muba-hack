Claude / Anthropic SDK
GonkaRouter implements
POST /v1/messages
with the full Anthropic Messages API surface (streaming + tool use included). Point an official Anthropic SDK at the gateway by overriding
base_url
and
api_key
.
Endpoint
https://api.gonkarouter.io/v1/messages
Recommended Model
MiniMaxAI/MiniMax-M2.7
1. Install the SDK
install.sh
Copy
# Python
pip install "anthropic>=0.40"
# Node / TypeScript
npm install @anthropic-ai/sdk
2. Python — one-shot (tested ✓)
claude_oneshot.py
Copy
from anthropic import Anthropic
client = Anthropic(
base_url="https://api.gonkarouter.io",
api_key="sk-xxxxxx",  # your GonkaRouter key
)
msg = client.messages.create(
model="moonshotai/Kimi-K2.6",
max_tokens=1024,             # keep ≥ 1024 — see "reasoning tokens" note below
messages=[
{"role": "user", "content": "Reply with just: pong"},
],
)
# content is a list of blocks; grab the first text block.
text = next((b.text for b in msg.content if getattr(b, "text", None)), "")
print(text)                       # -> "pong"
print(msg.usage)                  # -> input_tokens=…, output_tokens=…
3. Python — streaming (tested ✓)
claude_stream.py
Copy
from anthropic import Anthropic
client = Anthropic(
base_url="https://api.gonkarouter.io",
api_key="sk-xxxxxx",
)
# Idiomatic Anthropic streaming — text_stream yields each token chunk as a string.
with client.messages.stream(
model="moonshotai/Kimi-K2.6",
max_tokens=1024,
messages=[{"role": "user", "content": "Say hello in exactly three words."}],
) as stream:
for chunk in stream.text_stream:
print(chunk, end="", flush=True)
final = stream.get_final_message()
print()
print("usage:", final.usage)
4. TypeScript / Node
claude.ts
Copy
import Anthropic from "@anthropic-ai/sdk";
const client = new Anthropic({
baseURL: "https://api.gonkarouter.io",
apiKey: process.env.GONKA_API_KEY!,   // sk-xxxxxx
});
// One-shot
const msg = await client.messages.create({
model: "moonshotai/Kimi-K2.6",
max_tokens: 1024,
messages: [{ role: "user", content: "Reply with just: pong" }],
});
const text = msg.content
.filter((b): b is Anthropic.TextBlock => b.type === "text")
.map((b) => b.text)
.join("");
console.log(text);
// Streaming — idiomatic helper
const stream = client.messages.stream({
model: "moonshotai/Kimi-K2.6",
max_tokens: 1024,
messages: [{ role: "user", content: "Say hello in three words." }],
});
for await (const chunk of stream) {
if (chunk.type === "content_block_delta" && chunk.delta.type === "text_delta") {
process.stdout.write(chunk.delta.text);
}
}
const finalMsg = await stream.finalMessage();
console.log("\nusage:", finalMsg.usage);

1. Install Claude Code
install.sh
Copy
npm install -g @anthropic-ai/claude-code

2. Launch with an isolated HOME (recommended)
run-claude.sh
macOS / Linux
Windows (cmd)
Copy
# 1. Create an isolated HOME so Claude Code does NOT pick up your existing
#    ~/.claude/credentials OAuth session and silently ignore the env vars below.
mkdir -p /tmp/gonka-claude-home
# 2. Launch inside your project directory. Every env var matters — see below.

DISABLE_PROMPT_CACHING=1 \
claude
Use this exact incantation when you want Claude Code to route
cleanly through GonkaRouter
without touching your existing Anthropic OAuth session.
Only if you prefer PowerShell — "running scripts is disabled on this system"
The cmd steps above run
claude
fine. But if you launch it from
PowerShell
instead, npm's
claude.ps1
is blocked by default (
Restricted
execution policy). Run this
once
to allow local scripts for your own user:
allow-scripts.ps1
Copy
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
# answer Y when prompted. (In cmd you don't need this at all.)
What each env var does
HOME=/tmp/gonka-claude-home
—
isolates the credentials store.
Without this, Claude Code reads
~/.claude/credentials
, finds your existing OAuth session for Anthropic.com, and silently ignores
ANTHROPIC_AUTH_TOKEN
. The throwaway HOME forces it to fall back to the env-var path.
ANTHROPIC_BASE_URL
— domain root, no
/v1
suffix. The CLI appends
/v1/messages
itself.
ANTHROPIC_AUTH_TOKEN
— your GonkaRouter key. Sent as
x-api-key
. Note: it's
_AUTH_TOKEN
, not
_API_KEY
.
ANTHROPIC_MODEL
— primary model used for main reasoning. Pin to a Gonka model id (slashes preserved).
ANTHROPIC_SMALL_FAST_MODEL
— model used for sidecar tasks (file summaries, planner checks). Set it to the same Gonka model so every internal call still routes through your gateway.
DISABLE_PROMPT_CACHING=1
— the gateway does not implement Anthropic's prompt-caching headers; disable client caching to avoid
cache_control
requests that the gateway can't honour.

Gotchas
Already logged into Anthropic?
Without the isolated
HOME
the CLI will keep using OAuth and bill your Anthropic account instead. Verify routing by running
/status
inside the REPL — it should print
https://api.gonkarouter.io
as the base URL.
Working directory state.
The isolated HOME means a fresh session history every time. To keep history, replace
/tmp/gonka-claude-home
with a persistent path like
~/.gonka-claude-home
.
Model id is case-sensitive.
moonshotai/Kimi-K2.6
works,
Kimi-K2.6
alone returns
model not available for your channel
.

Gotchas
Model id is
gonka/<real-id>
.
The prefix is the provider id you registered, not the underlying
anthropic/
path. Slashes inside the model id are part of the id and must be preserved verbatim (
gonka/moonshotai/Kimi-K2.6
).
Daemon vs.
--local
.
The
--local
flag bypasses the Gateway daemon and dials your provider directly from the CLI process — useful for one-off scripts and CI where you don't want a long-running daemon. Omit it and the daemon (port 18789) handles routing.
Anthropic's own Claude Code CLI is different.
The official
@anthropic-ai/claude-code
CLI
does
honour
ANTHROPIC_BASE_URL
/
ANTHROPIC_AUTH_TOKEN
. If that's what you meant by "OpenClaw", see the Claude SDK tab — the env-var pattern there applies to that CLI too.

Gotchas
A 404 here is almost always the URL.
404 page not found
is the router's response to an unregistered path — it means the request reached us but the path was wrong. An invalid key returns
401
, and an unknown model returns
400
, so neither of those looks like a 404.
Output is capped at 4096 tokens.
Long agent turns get cut off with
MAX_TOKENS
. Omitting
max_tokens
yields an even lower default of 3072, and asking for more than 4096 is silently clamped back down, so the cap cannot be raised from the client. For reasoning models the thinking tokens count toward it too. Ask for shorter replies, or continue the turn after a truncation.
Model ids differ per gateway plan.
Vendor-prefixed ids like
MiniMaxAI/MiniMax-M2.7
and short ids like
kimi-k2.6
belong to different catalogs. Copy whatever the
Models
page shows for your key.
Requests are relayed by WorkBuddy's own backend.
Calls arrive via WorkBuddy's SaaS layer rather than straight from your machine, which is why its error reports carry two ids. When contacting support, quote the Trace ID from the error card.
